# GridBase V1.2.0

GridBase menambahkan audit aktivitas per akun dan konfirmasi sebelum menjalankan
query UPDATE atau DELETE. Rilis MINOR ini melanjutkan isolasi koneksi pada V1.1.0.

## Fitur dan perbaikan

- **Activity per akun:** telusuri aktivitas autentikasi, operasi koneksi, eksekusi
  query, metadata, dan permintaan ekspor dari panel Activity. Filter berdasarkan
  waktu, aktivitas, status, dan koneksi, dengan paginasi terbaru dahulu.
- **Admin audit:** `AUDIT_ADMIN_IDS` menentukan ID numerik GitHub yang dapat melihat
  aktivitas seluruh akun dan login gagal tanpa actor terverifikasi. Hak audit tidak
  memberikan akses ke koneksi atau kredensial pengguna lain.
- **Teks SQL pada audit:** aktivitas `query.execute` menyimpan SQL yang dikirim,
  fingerprint SHA-256, operasi, status, durasi, dan jumlah baris jika tersedia.
  Detail Activity menampilkan SQL sebagai teks, bukan HTML. Aktivitas non-query
  tidak menyimpan teks SQL.
- **Pencatatan sebelum JDBC:** intent dan metadata SQL disimpan sebelum query
  dijalankan. Kegagalan pencatatan awal memblokir operasi database. Jika pencatatan
  akhir gagal, respons operasi tetap dipertahankan dengan peringatan audit dan
  catatan pending; jangan langsung mengulangi query tulis.
- **Konfirmasi UPDATE/DELETE:** pop-up memperlihatkan koneksi dan SQL sebelum query
  dikirim, termasuk melalui tombol Run, Ctrl/Cmd+Enter, seleksi, dan CTE (`WITH`).
  Cancel tidak mengirim query atau menghapus hasil/history sebelumnya. Deteksi
  mencakup mutasi dalam CTE, dollar-quoted literals PostgreSQL, SEARCH/CYCLE, dan
  EXPLAIN ANALYZE/ANALYSE yang mengeksekusi mutasi. SELECT FOR UPDATE dan EXPLAIN
  tanpa eksekusi tidak memunculkan konfirmasi mutasi.
- **Audit ekspor:** permintaan CSV/JSON mereferensikan query berhasil milik pengguna.
  Unduhan dibatalkan jika pencatatan gagal. Catatan menunjukkan permintaan ekspor,
  bukan bukti file selesai disimpan.

## Upgrade dan konfigurasi

1. Hentikan instance yang menggunakan volume data yang sama sebelum membuat backup.
   Simpan `data/gridbase.sqlite` dan `data/credentials.key` bersama-sama. Jika sudah
   memakai build Activity sebelumnya, backup `data/audit.sqlite` secara terpisah;
   gunakan SQLite backup API/CLI bila aplikasi masih berjalan.
2. Ambil versi baru dan jalankan kembali backend Java. Audit memakai SQLite terpisah
   di `data/audit.sqlite` pada volume data yang sama. Schema audit versi 1 otomatis
   dimigrasikan ke versi 2 tanpa menghapus riwayat. Catatan lama tetap memiliki
   `sqlText: null` karena SQL sebelumnya tidak dapat direkonstruksi. Ini tidak
   mengubah schema profil koneksi yang sudah diperkenalkan V1.1.0.
3. Opsional: isi `AUDIT_ADMIN_IDS` dengan ID numerik GitHub dipisahkan koma, lalu
   restart. Nilai kosong tidak memberikan hak audit lintas akun.
4. Login ulang bila sesi berakhir dan klik Connect pada profil yang ingin dipakai;
   profil tetap dipulihkan dalam status disconnected setelah restart.

## Privasi dan batasan

- **SQL tersimpan sebagai teks biasa di audit dan backup-nya, termasuk literal dan
  komentar sensitif.** Hindari menaruh rahasia dalam query; batasi akses file,
  backup, dan hak admin audit. Pemilik aktivitas dan admin audit dapat membacanya.
- Audit tidak menyalin hasil baris, kredensial profil koneksi, token/cookie sesi,
  kode/state OAuth, request body lengkap, atau exception database mentah.
- Konfirmasi adalah pengaman UI, bukan otorisasi API, jaminan rollback, atau
  pengaman untuk semua jenis perintah SQL. Perintah selain UPDATE/DELETE serta
  efek fungsi/trigger tidak dicakup oleh konfirmasi ini.
- Audit tidak dihapus otomatis. Pending berarti hasil belum tercatat, bukan bukti
  bahwa SQL tidak dijalankan. SQLite audit dan database eksternal bukan satu
  transaksi atomik. Logout tetap mencabut sesi ketika penyimpanan audit terganggu.
- Activity memerlukan backend Java JDBC. Endpoint Activity pada backend Node
  legacy mengembalikan `501`.
- Binary lama yang hanya mendukung schema audit versi 1 tidak dapat membuka schema
  versi 2. Jika perlu rollback, hentikan versi baru dan pulihkan backup yang sesuai;
  jangan menurunkan angka schema secara manual.

## Validasi

- `npm test`: tes versi, SQL, metadata, workbench, HTTP, autentikasi, sesi,
  persistensi audit, migrasi, isolasi akun/admin, dan JDBC.
- `npm run check`: konsistensi versi, sintaks JavaScript, dan kompilasi Java.
- OpenAPI diperiksa dengan parser YAML yang menolak duplicate key.

Tes OAuth/JDBC memakai fixture; validasi tidak menjalankan mutasi pada database
eksternal. Panduan lengkap tersedia di
[README](https://github.com/yantodev/GridBase/blob/V1.2.0/README.md) dan
[VERSIONING](https://github.com/yantodev/GridBase/blob/V1.2.0/VERSIONING.md).
