# GridBase V1.1.0

GridBase kini menyimpan koneksi database secara privat untuk setiap akun GitHub.
Pengguna hanya dapat melihat dan memakai koneksi miliknya, termasuk kredensial,
query, metadata, status koneksi, dan koneksi default.

## Fitur dan perbaikan

- **Kepemilikan berdasarkan ID GitHub:** perubahan username tidak memindahkan koneksi,
  dan akun lain yang memakai username lama tidak memperoleh akses ke data tersebut.
- **Penyimpanan per akun:** SQLite memfilter setiap operasi menurut pemilik. Enkripsi
  AES-GCM mengikat kredensial ke ID pemilik dan ID koneksi. Batas 20 koneksi berlaku per akun.
- **Proteksi API:** ID koneksi milik akun lain mengembalikan `404` sebelum JDBC dibuka
  atau SQL dijalankan. Pemeriksaan mencakup Save, Test, Connect, Edit, Disconnect,
  Delete, query, dan seluruh endpoint metadata.
- **Cache browser per akun:** draft SQL, Recent queries, dan profil koneksi memakai
  namespace ID GitHub. Workbench dimuat setelah sesi terverifikasi. Tab lama disembunyikan
  dan dimuat ulang saat akun berubah; header `X-GridBase-Account` mencegah operasi
  tab lama berjalan memakai sesi akun baru dengan respons `409`.
- **Form tetap tersimpan saat berpindah tab:** verifikasi ulang akun yang sama
  mempertahankan isian dialog. Respons sesi yang terlambat tidak dapat menampilkan
  kembali workspace dari sesi lama.
- **Backend Node legacy:** satu koneksi Beeline dari environment hanya tersedia bagi
  ID pemilik yang dikonfigurasi. Pencocokan rute metadata diperketat agar variasi URL
  tidak melewati pemeriksaan pemilik.
- **Dokumentasi:** README, OpenAPI, `.env.example`, dan Compose menjelaskan isolasi akun,
  konfigurasi migrasi, dan respons pergantian akun.

## Upgrade dari V1.0.0

Profil lama belum memiliki informasi pemilik. Tentukan satu akun tujuan melalui
konfigurasi operator; login pertama tidak dapat mengklaim profil tersebut.

1. Hentikan seluruh instance yang menggunakan volume data yang sama.
2. Backup `data/gridbase.sqlite` dan `data/credentials.key` bersama-sama ke lokasi privat.
   Pada Docker, kedua file berada di volume `gridbase-data`.
3. Ambil **ID numerik** akun tujuan dari field `id` di
   `https://api.github.com/users/USERNAME`, lalu isi `.env` atau environment deployment:

   ```dotenv
   LEGACY_CONNECTION_OWNER_ID=ID_NUMERIK_GITHUB
   ```

4. Jalankan versi baru. Startup memindahkan seluruh profil tanpa pemilik ke akun tujuan
   dan mengenkripsi ulang kredensial dalam satu transaksi. Profil yang sudah memiliki
   pemilik tidak dipindahkan oleh migrasi berikutnya. Data rusak membatalkan seluruh
   transaksi migrasi.
5. Login ulang sebagai akun tujuan, lalu klik **Connect** pada profil yang ingin dipakai.
   Profil tersimpan dipulihkan dalam status disconnected setelah restart.

Jika `LEGACY_CONNECTION_OWNER_ID` kosong, profil lama tetap tersimpan tetapi tersembunyi
dari semua akun. Konfigurasi ini dapat dikosongkan setelah migrasi selesai. Backend Node
legacy tetap memerlukan nilai tersebut untuk memberikan akses ke koneksi environment.

Schema SQLite naik ke **versi 2**. Untuk kembali ke V1.0.0, hentikan versi baru lalu
pulihkan **database dan key** dari backup sebelum upgrade. Cache browser lama tanpa
informasi pemilik tidak dimuat; tambahkan kembali profil browser yang belum disimpan
di server dan isi ulang kredensialnya.

## Validasi

- `npm test`: 73 tes Node dan 13 program tes Java.
- `npm run check`: sinkronisasi versi, pemeriksaan sintaks JavaScript, dan kompilasi Java.
- Kontrak OpenAPI dan Compose diperiksa dengan parser YAML yang menolak duplicate key.
- Cakupan mencakup dua akun, akses lintas akun sebelum JDBC, request paralel, pergantian
  username, restart, migrasi atomik, cache browser, dan pergantian sesi.

Tes OAuth dan JDBC memakai fixture; pengujian tidak menjalankan SQL pada database eksternal.
Panduan lengkap tersedia di [README](https://github.com/yantodev/GridBase/blob/V1.1.0/README.md)
dan [VERSIONING](https://github.com/yantodev/GridBase/blob/V1.1.0/VERSIONING.md).
