# GridBase V1.3.0

GridBase menambahkan MCP berbasis token per akun untuk Hermes Agent dan Codex CLI,
serta label DB, History, dan Logs pada sidebar. Rilis MINOR ini mempertahankan
workbench, sesi GitHub, dan isolasi koneksi yang sudah ada.

## Fitur

- Endpoint MCP Streamable HTTP `/mcp` dengan autentikasi bearer, JSON-RPC 2.0,
  inisialisasi, discovery tool, metadata dan eksekusi SQL pada koneksi yang diberikan.
- Settings / MCP per akun untuk membuat token bernama, memilih scope `read_only`
  atau `full_access`, koneksi tersimpan eksplisit, masa berlaku 30/90/365 hari,
  dan pencabutan token. Token mentah ditampilkan sekali; server menyimpan hash.
- Grant immutable terikat ke generasi profil. Edit kredensial/pengaturan atau
  hapus/buat ulang profil membatalkan grant lama, bukan memperluas akses diam-diam.
- `read_only` mensyaratkan profil khusus dengan kredensial database/storage berizin
  baca pada semua database: PostgreSQL, MySQL, Spark Thrift/Hive. Filter AST SQL
  memakai subset SELECT/CTE konservatif; PostgreSQL/MySQL juga memakai transaksi
  read-only. Hive tidak mengandalkan flag JDBC yang tidak didukung driver.
- Batas hasil independen dari SQL LIMIT: maksimal 500 baris dan 1.000 entri metadata,
  respons maksimal 1 MiB, deadline serta worker pool MCP terbatas.
- Logs mencatat sumber MCP, akun terverifikasi, ID/nama token nonrahasia, SQL,
  hasil, durasi dan counts. Kegagalan tool HTTP 200 tidak salah dicatat sebagai sukses.
  Audit intent tersimpan sebelum JDBC; kegagalan final audit mempertahankan hasil
  aktual dengan `auditIncomplete` dan request ID.
- UI token memakai render teks aman, pemilihan koneksi eksplisit, serta menghapus
  one-time secret pada penutupan, perubahan akun dan respons asinkron yang basi.
- Panduan konfigurasi Hermes/Codex dan batas keamanan tersedia di `docs/MCP.md`.
  Backend Node legacy menolak MCP dan API token dengan `501`.
- Routing aset `/mcp.js` dipisahkan dari transport `/mcp`, sehingga tombol Settings
  memuat modul UI melalui sesi browser sementara endpoint MCP tetap wajib bearer.
- Metadata PostgreSQL/MySQL memperlakukan nama schema/tabel sebagai identifier
  literal, termasuk `_`, `%`, dan karakter escape driver. Nama yang mirip tidak
  tercampur pada daftar tabel atau deskripsi kolom di workbench maupun MCP.

## Upgrade

1. Hentikan instance yang berbagi volume dan buat backup konsisten. Simpan
   `data/gridbase.sqlite` bersama `data/credentials.key`, serta `data/audit.sqlite`.
   Setelah memakai MCP, backup `data/mcp.sqlite` juga; backup token lama dapat
   mengembalikan keadaan sebelum pencabutan sehingga tidak boleh dipulihkan sembarang.
2. Jalankan backend Java baru. Audit schema 1/2 dimigrasikan ke schema 3 tanpa
   menghapus histori; field token pada catatan lama tetap null. Profil mendapat
   generasi tersimpan dan deklarasi MCP read-only lama default false.
3. Siapkan identitas read-only khusus di database/catalog/storage, lalu konfirmasi
   deklarasi tersebut di connection manager sebelum menerbitkan token read_only.
   Checkbox tidak membuat atau membuktikan izin database.
4. Untuk akses jarak jauh, gunakan APP_URL HTTPS dan reverse proxy TLS tepercaya.
   Java listener tetap plaintext; batasi akses langsung serta jaga hop proxy-app privat.
5. Buat token melalui Settings / MCP dan simpan pada secret environment client.
   Jangan menyimpan bearer pada URL, source control, log atau browser storage.

Binary lama tidak mendukung audit schema 3. Untuk rollback, hentikan versi baru
lalu pulihkan backup yang cocok; jangan menurunkan angka schema secara manual.

## Batas keamanan

- `full_access` hanya akses SQL pada profil akun yang diberikan, bukan admin aplikasi
  atau akses kredensial. Izin database tetap berlaku dan ceiling profil read-only
  tetap membatasi token full_access.
- Disconnect workbench dan logout browser tidak mencabut token. MCP dapat memakai
  profil tersimpan setelah restart. Cabut token melalui Settings untuk menghentikan
  permintaan baru; pencabutan tidak membatalkan write yang sudah berjalan.
- Konfirmasi UPDATE/DELETE browser tidak berlaku pada MCP. Client AI harus meminta
  persetujuan sebelum write; annotations MCP bukan jaminan persetujuan manusia.
- Filter SQL tidak membuktikan seluruh view/UDF/operator/storage handler bebas efek
  samping. Izin database/storage dan administrasi objek tepercaya adalah boundary.
- Timeout/pembatalan tidak menjamin driver menghentikan pekerjaan database. Driver
  yang macet tetap menahan slot worker; jangan otomatis mengulang write tak pasti.
- SQL lengkap, termasuk literal/komentar sensitif, tetap disimpan dalam audit. Jangan
  menyisipkan rahasia dalam query dan lindungi audit/backup serta hak admin audit.

## Validasi

- `npm test`, `npm run check`, validasi schema OpenAPI/duplicate YAML keys dan
  `git diff --check` dijalankan pada persiapan fitur.
- Tes memakai HTTP, SQLite nyata, dua akun dummy, JDBC fixture dan MCP SDK asli:
  inisialisasi/discovery, SELECT fixture, penolakan write read_only, isolasi token,
  migrasi, invalidasi generasi, deadline dan kapasitas driver yang mengabaikan cancel.
- Bentuk konfigurasi Hermes/Codex diperiksa memakai konfigurasi terisolasi. Ini bukan
  bukti izin database produksi atau prompt persetujuan write client; verifikasi
  deployment dan privilege dilakukan operator tanpa write-probe pada produksi.
