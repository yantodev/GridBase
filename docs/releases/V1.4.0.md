# GridBase V1.4.0

Rilis MINOR ini menambahkan fondasi engine lokal terpisah untuk pengembangan
client mandiri, sekaligus memperbaiki isolasi build Java dan validasi file SQLite.
Mode web/server yang sudah tersedia tetap memakai login GitHub dan isolasi akun.

## Fondasi engine lokal

- Identitas lokal berbasis profil pengguna OS dipisahkan dari identitas GitHub.
  Entry point lokal memakai workspace privat, kunci dari host, dan lock proses;
  data server tidak diadopsi atau dimigrasikan otomatis.
- Bootstrap engine lokal memakai protokol stdin terbatas dan capability per
  peluncuran. Capability diperlukan pada API lokal, termasuk health/session;
  cookie browser atau bearer MCP tidak dapat menggantikannya.
- MCP lokal merupakan listener loopback terpisah dan nonaktif secara default.
  Pengaktifan serta port disimpan dalam pengaturan terautentikasi dan terikat
  pemilik/kunci workspace. Token, grant, batas SQL, kebijakan read-only, dan audit
  memakai implementasi bersama, bukan jalur eksekusi SQL baru.
- Shutdown/EOF dan pergantian port menutup seluruh listener yang dimiliki engine,
  termasuk kandidat yang belum aktif, sebelum menunggu worker selesai. Workspace
  tetap terkunci selama JDBC yang mengabaikan interupsi masih berjalan; write
  yang hasilnya tidak pasti tidak dicoba ulang otomatis.

## Perbaikan

- Build secara eksplisit menargetkan Java 17 dan menghormati `JAVA_HOME`.
  Pemeriksaan build memakai direktori sementara; setiap startup memakai output
  class runtime unik agar build berikutnya tidak merusak JVM yang masih aktif.
  Perbaikan yang semula disiapkan untuk V1.3.2 disertakan dalam rilis ini;
  V1.3.2 tidak diterbitkan terpisah.
- Validasi WAL/SHM SQLite tidak membuat, memperbaiki izin, atau menciptakan ulang
  file sementara milik SQLite. Hilangnya file atau pergantian identitas file
  native ditangani melalui validasi ulang terbatas dengan pemeriksaan parent,
  database utama, pemilik, tipe, dan izin tetap ketat. Kegagalan tidak ditutupi
  dengan retry query atau pengabaian durable audit intent.
- Perilaku shutdown server tetap berbeda dari engine lokal: perbaikan lifetime
  lock lokal tidak menambahkan penantian JDBC tanpa batas pada shutdown server.

## Cakupan dan batasan

- Ini bukan rilis aplikasi desktop siap instal. Electron shell, supervisor/broker
  native, penyimpanan kunci native, installer `.exe`/`.deb`, dan extension VS Code
  belum tersedia. Tidak ada klaim dukungan native Windows atau instalasi offline
  end-to-end pada rilis ini.
- Pengujian native Windows/AppData/DACL/reparse serta penolakan pemilik POSIX yang
  berbeda belum diverifikasi. Hasil fixture Linux tidak menggantikan penerimaan
  pada platform tersebut.
- Jalur engine lokal adalah fondasi integrasi host, bukan pengganti login GitHub
  pada workbench web. Menjalankan server biasa tidak mengaktifkan mode offline
  atau listener MCP lokal tambahan.
- Validasi deterministik membuktikan kasus pergantian file SQLite yang ditemukan,
  bukan jaminan bahwa seluruh kemungkinan kegagalan konkurensi telah dieliminasi.
- Proses JDBC yang tidak merespons interupsi dapat menahan shutdown engine lokal.
  Timeout atau putusnya respons tidak membuktikan bahwa SQL belum dijalankan.

## Upgrade server

Restart layanan setelah memperbarui source. Sesi browser dalam memori dan koneksi
aktif berakhir; login ulang dan Connect profil tersimpan bila diperlukan. Data
aplikasi dan kunci kredensial harus tetap dipertahankan. Jangan menghapus output
class runtime lama selama masih dipakai proses yang aktif.

Tidak ada prosedur adopsi data server ke profil lokal, perubahan izin database
remote, atau kebutuhan mencoba query tulis untuk memverifikasi upgrade.
